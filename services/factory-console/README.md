`scripts/console.sh dev --port 5174` 실행 후 [3D 디자인 시안](http://127.0.0.1:5174/?preview=3d)을 연다. 기존 5173 서버가 실행 중이면 별도 개발 포트 5174를 사용한다. 이 미리보기는 DB·서버 없이 기본 공장 설정으로 표시하며 생산을 시작하거나 SSE에 연결하지 않는다.

사선/평면 시점, 회전·확대·이동, 이름/경로/부품 구역 표시와 대상 선택을 확인할 수 있다. 차량·차체·예약은 **정적 디자인 예시**다. 1차 색감 승인을 받았으며 실제 관측·충돌 회피 구현은 아래 2차 확인 항목을 따른다.

## 현재 실행과 화면 · 2026-10-11

서버/DB는 Compose로 켠다. 정적 Docker/Nginx http://127.0.0.1:5173 은 실제 REST/SSE 관측용이며 프로세스 실행기가 없다. 시작·중단·수동 복구는 Python 3.12 경로를 설정한 Vite에서 사용한다.

```sh
scripts/dev-stack.sh up
# 가상환경이 없을 때 scripts/simulator.sh setup
scripts/console.sh install
FACTORY_SIMULATOR_PYTHON="$PWD/.build-cache/simulator-venv/bin/python" scripts/console.sh dev --port 5174
```

http://127.0.0.1:5174 의 선택지는 **1대 정상 / 3대 정상 / 5대 장애·수동 복구**다. 웹 시작은 --traffic을 자동 적용한다. 5대 장애 시나리오는 점검 시작 → 조치 완료 → 2초 확인 후 재가동이며 자동 복구하지 않는다. `알람 확인`은 별도 확인 기록이다. 실행기의 TCP 대상은 현재 127.0.0.1:9090 고정이다. `vite preview`도 실행기를 제공하지 않는다.

Windows 네이티브는 [Windows 안내](<../../docs/development/Windows Docker 없이 실행.md>)의 up이 Python 경로와 Vite 5173을 준비한다. Vite 종료/설정 재시작은 관리 중인 Python을 중단시킨다. CLI로 만든 run을 조회하는 것만으로 수동 제어 연결을 만들지는 않는다.

현재 공장은 3D 기본, 2D SVG 대체 보기다. 공장 탭은 상태 요약·설비/차량·ASM 부품 재고를 보여 주고 **차체 조회 / 품질 · 알람 / 기록**은 별도 탭이다. 선택한 run과 상세의 관측 기준을 유지한다. 임의 브라우저 생산값을 만들지 않는다.

- 차량 버튼 → AGV·AMR **3인칭 추적**. 드래그로 상대 시점, 휠로 거리를 바꾸고 시점 초기화로 복귀한다. AGV는 **1인칭 전면**도 선택할 수 있다.
- 설비·차체·Bay 클릭으로 기존 상세/기록을 조회한다. 경로·목적지·적재·설비 동작은 실제 관측을 따르며 로봇팔 동작은 시각적 표현이다.
- ASM별 초기 2키트, 작업 시작 시 소비, AMR 실제 하차 후 재고 증가, 보급 중 수량/용량/남은 수요를 반영한다. 정상 실행에서도 부품 구역을 표시한다. 1대는 초기 재고만으로 충분해 AMR이 대기할 수 있다.
- 상태 알람 확인은 고장/슬롯을 직접 바꾸지 않는다. 수동 장애 패널은 로컬 실행기의 별도 명령/응답을 사용한다. 이력은 `maintenance.json`에 남으며 서버의 영속 정비 관리 API로 확장한 것은 아니다.

원본 실행과 스냅샷의 runId/epoch/revision이 바뀌면 이전 장면과 보간을 이어 붙이지 않는다. 관측 중단 시 확정 위치를 표시한다. `?preview=3d/equipment/amr`의 개별 미리보기는 정적 시안이므로 실시간 증거로 사용하지 않는다.

## 데이터와 연결 상태

개발 서버 `/api`·`/readyz`의 기본 중계 대상은 http://127.0.0.1:8082다. 이 디렉토리의 로컬 `.env`에서 OPERATIONS_PROXY_TARGET으로 변경할 수 있다. Compose Nginx는 operations-service로 같은 경로를 중계하고 SSE buffering/cache를 끈다. 브라우저에 DB 암호를 넘기지 않는다. `/healthz`는 정적 파일 제공, `/readyz`는 관제 DB 준비이며 제조 데이터 LIVE와 다르다.

`ConsoleFeed`는 실행/연결별 이전 요청·연결·타이머를 정리한다. 첫 유효 SSE가 epoch를 정하고 같은 epoch의 더 큰 revision만 적용한다. sourceSeq 감소나 예전 실행/epoch의 늦은 REST가 현재 상태를 덮지 못한다. 중복/heartbeat/onopen은 새 관측이 아니다. 유효 묶음3초 부재는 마지막 확인값,10초 부재는 화면 연결 확인 필요이며 마지막 공장 보고 후 경과 시간도 별도로 판단한다. 종료 ARCHIVED는 보관값이다.

`ScopedQueries`는 실행·epoch·대상·필터와 요청 순서로 조회 응답을 구분한다. 교체한 요청을 취소하고 5초를 제한한다. 품질 합계/차트는 같은 기간의 두 응답이 모두 맞을 때 함께 표시한다. 이력·알람 확인 응답은 물리 상태를 바꾸지 않는다. 같은 실행의 새 묶음과 재연결은 선택/필터를 유지한다. 다른 실행을 선택하면 상세 선택과 현재값을 비운다.

## 3D 실제 관측·충돌 회피 (2차 확인)

`?view=3d` 또는 **3D 공장**으로 연다. 기본 화면도 3D이며 `?view=2d`로 2D를 직접 연다. Python에서 계산한 경로와 관측 위치, 실제 적재, Bay 슬롯, 설비 상태를 표시하고 기존 상세창에 연결한다. 최신 관측 사이에서만 같은 경로의 진행량을 보간하며 경로·적재·실행 변경이나 통신 지연에는 원자적으로 확정 위치를 적용한다. `?preview=3d`는 기존 정적 디자인 검토용이다.

로컬 시작 버튼을 켜려면 `FACTORY_SIMULATOR_PYTHON="$PWD/.build-cache/simulator-venv/bin/python" scripts/console.sh dev --port 5174`로 실행한다. 새 웹 실행은 `--traffic`을 자동 사용한다. 정상 CLI는 TCP 환경 변수와 `--connected-demo --traffic`을 사용한다. 수동 복구는 웹 버튼으로 시작한다. 먼저 수정된 수신·운영 서비스를 기동해야 한다. 이전 실행은 충돌 규칙 미적용으로 표시한다.

입고·출고 보관은 대표 차체+수량으로 집계하며 모든 개별 차체는 목록/검색/상세에서 조회 가능하다. 기계 내부 인계는 별도 애니메이션 없이 확정 상태로 전환한다. 양보 대기는 호박색 링과 차량 목록/상세의 텍스트로 표시한다. 상단 차량 시점에서 AGV-001·002의 가상 전면 카메라를 선택할 수 있다.


새 3D 실행은 교통 정책 4를 사용한다. 빈 설비에는 직접 접안해 인계하고, 대기가 필요하면 Bay에 내려놓는다. Bay 대기 차체도 AGV가 설비로 다시 운반한다. 설비·Bay·차량·차체 외형은 25% 커졌으며 동일한 설정으로 충돌 영역을 계산한다. AGV 상태창은 화면 폭 116px이며 상태 글자를 줄였다. 과거 실행의 물리 배치는 보존된다.


교통 정책 3은 A* 통로 계획과 구간별 통행 예약을 사용한다. 공정 접안과 주행선을 분리하고, 동·서 방향 주행선과 좁은 접안 진입로를 구분했다. 회전 중 정지, 가감속, 적재물을 포함한 충돌 여유를 시뮬레이터와 3D 화면이 같은 시간 곡선으로 표시한다. 회색 선·화살표는 통로이고 파란 선은 현재 작업의 계획 경로다. 막힌 경우 우선 대기하며, 정차 지점에서만 재계획하거나 지정 대기 위치로 양보한다. 새 규칙은 새 실행부터 적용된다. 자세한 재현 명령과 결과는 `docs/work-notes/작업 49. 통로 기반 경로와 구간 예약.md`를 참고한다.


정책 4는 양방향 주행 통로, 직선 연속 주행, 저속 접안 후진을 사용한다. 인계할 때마다 먼 주차장으로 복귀하지 않고 짧은 공정 완료를 현장에서 기다린다. 출고 접안점과 다른 차량의 목적지를 막는 자리만 비운다. 정책 3은 과거 실행 재생용으로 유지한다.

개발 서버의 실행 버튼 옆 **시뮬레이션 중단**은 현재 이 실행기가 시작한 Python만 종료한다. 중단 완료까지 중복 시작을 막고, 마지막 관측 기록은 보존한다. 일시정지/이어하기 기능이 아니며 다음 시작은 새 run이다. 정적 배포 서버에는 프로세스 실행기가 없다. 상세 검증은 `docs/work-notes/작업 50. AGV 동선 효율 복구와 시뮬레이션 중단.md`를 참고한다.


적재 중 후진을 금지하고 빈 차량의 접안 출발만 제한적으로 후진하도록 보완했다. 모든 생산·출고가 끝나면 AGV는 외곽 통로로 초기 위치에 돌아오며 화면에 `최종 복귀 → 초기 위치`를 표시한다. 상세 기록: `docs/work-notes/작업 51. 적재 전진 보장과 최종 외곽 복귀.md`.


## 상세 설비 모델과 AGV 1인칭 (작업 53)

승인된 `?preview=equipment`의 모델을 실제 관제에 적용했다. ASM-01·02는 롤러/클램프/관절 로봇/제어반, QC-01은 검사 게이트와 스캐너, AGV·AMR은 센서/범퍼/적재 롤러, Bay·부품 선반·입출고 구역은 지지대와 적재 구조를 사용한다. 설비 동작과 표시등은 관측 상태를 따르며 로봇 동작은 시각적 표현이다. 기계 내부 인계는 기존 확정 위치 전환을 유지한다. 시안의 고정된 25초 인계 애니메이션을 실시간 생산 동작으로 사용하지 않는다.

상단 **차량 시점 → AGV-001/002 → 1인칭 전면**으로 전환한다. 현재 기본 차량 시점은 3인칭 추적이며 AMR에도 제공한다. 적재물 앞의 가상 렌즈가 관측 위치/방향을 따라가며 관측이 멈추면 같이 멈춘다. 전체 공장 버튼으로 복귀한다. 새 실행 선택 시 이전 차량 카메라는 초기화된다. 실제 영상이나 자율주행 인식 센서 시뮬레이션은 아니다.

메인 화면은 실행/시작/중단, 생산 요약, 3D 공장과 설비·차량 현황으로 구성한다. **차체 조회**, **품질·알람**, **기록**은 별도 탭이며 연결 진단과 실행 ID는 접어두었다. 기존 조회 및 기록 데이터는 유지한다.

카메라 방향/렌즈 위치, 적재 모델과 설비의 기존 충돌 영역 준수, 개별 차체 색상과 설비 램프 분리를 검증한다. 재현: `scripts/console.sh test`, `scripts/console.sh build`. 시작/중단 버튼은 기존과 같이 로컬 Vite 실행기에서만 제공한다.

## 관측 사이의 연속 재생 (작업 61)

3D 공장 전체는 수신 시각 기준 600ms의 관측 버퍼로 재생한다. 같은 물리 관측의 SSE 재발행으로 이동을 다시 시작하지 않고, 정지 차량의 인계 때문에 다른 차량의 보간을 끊지 않는다. 경로가 달라지는 전환은 임의 직선으로 잇지 않으며 관측이 끊기면 마지막 받은 위치에서 멈춘다. 적재·재고·설비 표시도 같은 3D 재생 시점을 따른다. 상세 패널과의 짧은 시차는 이 표시 버퍼 때문이다.

추적 카메라는 설비 경계 상자로 가림을 검사한다. 상세 모델의 모든 삼각형을 매 프레임 검사하지 않는다. 현재 콘솔 테스트는 23개이며 기록 재생 검증은 `node scripts/verify-scene-playback.mjs <originals.ndjson>`을 저장소 루트에서 실행한다. [작업 기록](<../../docs/work-notes/작업 61. 3D 관측 재생 끊김과 추적 카메라 부하 개선.md>)을 참고한다.

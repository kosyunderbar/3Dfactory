# 작업 31. S07-03 품질 차트와 알람 확인·기록 조회

> 작업 ID: S07-03 · 작업일: 2026-10-05 · 상태: 완료

## 이번 작업은 무엇인가

화면에 ‘품질 · 알람’과 ‘기록 조회’를 추가했다. 검사 건수, PASS, FAIL, 불량률과 시간별 그래프를 함께 보고, 발생한 알람에 읽었다는 확인 기록을 남길 수 있다. 공장 상태의 판단은 기존 Python/관제 서버가 맡고 Vue는 결과를 표시한다.

## 기술의 역할

| 구성 | 쉬운 역할 |
|---|---|
| quality / trends REST | 같은 기간의 검사 합계와 시간별 검사 수를 DB에서 읽기 |
| Apache ECharts 6.1.0 | 서버가 계산한 시간별 수치를 막대 차트로 그리기 |
| QualityPanel.vue | 기간 선택, 합계와 차트의 함께 갱신, 표 제공 |
| AlarmPanel.vue / 확인 POST | 운영자가 알람을 읽은 시각과 확인자 저장 |
| 전체 SSE 묶음 | 확인 정보와 실제 복구 상태를 새로 관측하기 |
| RecordPanel.vue | 사건/알람의 기간·종류·상태·심각도별 과거 조회 |

ECharts는 기획서에 이미 정한 차트 도구다. 정확한 6.1.0을 package-lock에 고정했고 Vue/JavaScript/Vite나 서버 기술을 교체하지 않았다. 필요한 막대 차트·컴포넌트·SVG 렌더러만 가져오며 품질 화면을 처음 열 때 별도 모듈로 읽는다. [공식 모듈 사용 안내](https://echarts.apache.org/handbook/en/basics/import/)를 따랐다.

## 합계와 차트의 시각을 맞추는 방법

조회 시점의 UTC 끝 시각과 최근 5분·15분·1시간의 시작을 한 번 정한다. quality와 trends를 **같은 from/to**로 읽고 두 응답이 모두 맞을 때 함께 표시한다. 차트만 새 기간으로 바뀌고 합계가 옛 기간에 남지 않는다. 시간별 버킷은 1분이며 최대 1시간이다. 끝 시각은 미포함이다.

데이터는 inspection_result의 검사 사실이다. 지금 GOOD에 있는 차체 수를 검사 실적으로 세거나 브라우저에서 랜덤 숫자를 만들지 않는다. 검사 0건이면 불량률은 0%가 아닌 ‘—’다. 10초마다 또는 ‘품질 새로고침’으로 읽는다. 조회 실패 시 마지막 조회값과 기간을 보존하고 실패를 안내한다. 그래프와 같은 숫자를 표로 펼칠 수 있고, 한국어 접근성 설명도 같은 합계를 사용한다.

## 확인과 복구는 어떻게 다른가

‘알람 확인’은 operatorId로 읽었다는 기록을 저장한다. 화면은 성공 답장을 받아도 설비/슬롯/알람을 임의 변경하지 않는다. 다음 실제 전체 묶음이 확인자·시각을 표시한다. 고장 복구와 Bay 반환은 Python의 정상화·셀 진입 이후 새 보고로만 바뀐다. 원격으로 설비를 복구하는 버튼은 이번 기획 범위가 아니다.

실제 ASM-01 정지 알람을 s07-operator로 확인한 뒤에도 conditionActive=true와 차체/예약/슬롯을 유지했다. 이후 실제 복구 보고에서 복구 시각과 확인 이력이 함께 남았다. Bay 만석 WARNING과 설비 정지 CRITICAL도 별도 원인으로 표시했다.

## 필요한 검증

실제 정상 등록 차체 5대의 최종 검사 5/PASS 4/FAIL 1과 불량률 20.0%를 두 DB의 검사 사실, 같은 구간의 quality/trends, Chrome 차트/표로 대조했다. 검사 전 0건/‘—’도 확인했다. Node 요청 경계 사례는 두 조회 중 일부만 성공하거나 예전 기간 응답이 늦게 왔을 때 부분 표시를 막는지 확인한다. 변경하지 않은 Java/SQL 검증 전체를 재실행하지 않았다.

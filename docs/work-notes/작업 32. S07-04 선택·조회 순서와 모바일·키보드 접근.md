# 작업 32. S07-04 선택·조회 순서와 모바일·키보드 접근

> 작업 ID: S07-04 · 작업일: 2026-10-05 · 상태: 완료

## 이번 작업은 무엇인가

공장 상태가 계속 바뀌어도 사용자가 보고 있던 차체·검색·기록 조건이 흔들리지 않게 했다. 늦은 답장이 새 실행의 정보를 덮지 못하도록 했고 작은 화면과 키보드로도 주요 기능에 접근하도록 했다.

## 웹개발에서 왜 필요한가

차체 A의 이력을 요청한 뒤 B를 선택했는데 A의 답장이 늦게 오면 B의 창에 A의 기록이 섞일 수 있다. 실행을 바꾸거나 품질 기간을 바꿀 때도 같은 문제가 생긴다. 요청을 취소하는 것만으로는 이미 도착 중인 답장을 막지 못하므로 **요청의 소속과 순서를 확인**한다.

| 구성 | 쉬운 역할 |
|---|---|
| ConsoleFeed의 generation/epoch/revision | 현재 전체 상태의 실행·서버·수신 순서 구분 |
| ScopedQueries의 scope/channel/ticket | 현재 대상·필터에 속한 마지막 조회만 받아들이기 |
| AbortController / 5초 제한 | 교체한 요청과 오래 기다린 요청 정리 |
| ref / v-show | 탭을 바꿔도 검색·필터 값을 보존 |
| native dialog / tabindex / Enter / Space | 마우스 없이 지도 상세 열기와 닫기 |
| CSS media query / overflow | 모바일에서 한 열 배치, 지도·표 안에서만 가로 이동 |

## 유지하거나 비우는 기준

같은 실행의 새 SSE나 재연결은 선택·검색·필터를 유지한다. 상세의 현재값만 같은 묶음으로 갱신한다. 다른 실행으로 바꾸면 이전 실행의 선택 창과 현재값을 비우고 새 실행의 보고를 기다린다. 검색 조건과 화면 탭은 유지한다. 예전 실행/epoch의 조회 결과는 적용하지 않는다.

이력 조회는 새 보고마다 다시 시작하지 않는다. watch의 기준을 실행·epoch·대상·필터 값으로 고정했다. 이전에는 배열 watch가 매 묶음마다 새 배열을 만들어 페이지 기준을 흔들 수 있었으므로 실제 값의 문자열로 비교한다. 현재 물리 상태는 REST 이력/품질/확인 응답으로 덮지 않는다.

실제 Chrome에서 발견한 fetch 호출 문제도 수정했다. 브라우저 내장 fetch를 클래스 속성으로 그대로 호출하면 잘못된 호출 대상 때문에 실패할 수 있었다. 기본 호출을 `(...args) => fetch(...args)`로 감싸 기존 feed와 새 조회 모듈 모두 실제 브라우저에서 정상 동작하도록 했다.

## 모바일과 키보드

관제 영역으로 건너뛰기 링크, 화면 탭·검색·필터·상세 버튼에 접근할 수 있다. SVG 대상은 Enter/Space로 열고 Escape로 창을 닫는다. native dialog가 창 안의 초점 이동과 원래 버튼으로 복귀를 처리한다. 색상 외에 이름·숫자·테두리도 사용하고 reduced motion을 따른다.

실제 390×844에서 태그 창 폭 352px와 문서 폭 390px를 확인했다. 전체 페이지 가로 넘침 없이 검색과 상세를 사용했다. 넓은 지도는 내부 스크롤로 보며 좌표를 작게 눌러 뭉개지 않는다. 데스크톱에서도 지도·품질·이력의 실제 데이터를 확인했다. 키보드로 Bay 상세를 열고 Escape로 닫았을 때 원래 선택 버튼에 초점이 돌아왔다.

## 필요한 최소 검증과 다음 작업

Node 총 5개(기존 feed 2 + 요청 범위 2 + 표시 데이터 경계 1), Python 신규 2개와 기존 송신 압력 회귀 1개, Vue 빌드와 실제 전체 시나리오를 공유했다. Java/API/DB 구조는 변경하지 않았으므로 전체 Java나 모델 테스트 묶음을 추가로 반복하지 않았다. 실패를 고친 경우와 최종 빌드 확인만 필요한 만큼 재실행했다. **테스트는 최소한으로, 꼭 필요한 것만 수행한다.**

실제 소스 중단에서 같은 차체/차량 좌표와 예약을 보존하고 마지막 확인값을 표시했다. 의도적인 공장 PAUSED 중에는 보고를 계속 허용하도록 SourceSession을 수정했다. 물리 tick/자동 재개는 허용하지 않고 송신 대기 상한도 유지한다. 보고가 없을 때 상태를 정상이라고 추정하지 않는다.

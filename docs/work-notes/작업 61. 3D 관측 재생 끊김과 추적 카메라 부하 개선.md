# 작업 61. 3D 관측 재생 끊김과 추적 카메라 부하 개선

2026-10-11

사용자가 시뮬레이션 중 간헐적으로 화면이 끊기는 현상을 지적했다. 실제 양보·정지와 화면 재생 문제를 구분하고, 관측 재생 코드를 수정했다.

## 확인한 원인

- 기존 화면은 새 스냅샷마다 이전→현재의 보간 타이머를 다시 시작했다. 수신 간격이 짧으면 아직 도달하지 못한 지점으로 기준이 바뀌고, 길면 중간에 보간이 끝나 정지할 수 있었다.
- 물리 관측 시간이 같은 SSE 재발행도 새 프레임으로 처리해 보간을 해제했다.
- 한 차량의 정지 상태·적재 변경도 차량 전체의 보간을 끊었다.
- 로봇팔은 최신 스냅샷 시간만 사용해 보고 주기마다 자세가 바뀌었다.
- 3인칭 카메라는 매 프레임 정적 상세 모델 전체의 삼각형을 검사하고 월드 행렬을 강제 갱신했다.

## 수정

`scene3d/playback.js`에서 **600ms 수신 버퍼와 공장 공통 재생 시각**을 사용한다. 프레임을 받을 때 이동을 재시작하지 않으며, 같은 물리 관측의 반복 보고는 재생 시각을 건드리지 않는다. 차량 위치·적재·경로·설비·부품 상태를 공통 시점에 전환한다. 로봇팔도 이미 수신한 두 관측 사이의 시각으로 표현한다.

정지한 차량의 위치와 방향이 같으면 적재/상태가 바뀌어도 다른 차량의 보간을 유지한다. 움직이는 차량의 서로 다른 경로를 임의 직선으로 잇지 않는다. 미수신 미래 위치를 예측하지 않으며 긴 관측 공백·run/epoch 전환·정지/연결 단절은 버퍼를 비우거나 마지막 확인값에서 멈춘다. 버퍼는 최대 16개다.

`factory-scene.js`의 카메라 가림 검사는 미리 계산한 정적 설비 경계 상자로 바꿨다. 차체 물류의 충돌 판정과 렌더링 외형은 변경하지 않았다. `App.vue`의 큰 불변 관측/배치는 `shallowRef`로 보관하고, 차체 모델을 같은 부모에 매 프레임 다시 붙이지 않도록 했다.

3D가 보고 수신보다 약 0.6초 늦게 표시되는 절충이 있다. 상세 패널은 최신 보고를 사용한다. 실제 양보·접안·회전 정지는 유지하고, 안전하게 연결할 수 없는 이동 경계는 여전히 관측 위치로 전환한다. 이 변경이 모든 환경의 GPU 부하나 서버 지연까지 해결했다는 뜻은 아니다.

## 검증

- 콘솔 전체 **23개 테스트 통과** 및 Vue 프로덕션 빌드 성공. 추가 4개 테스트는 수신 간격 변동·중복 보고·정지 중 인계·경로 변경·연결 단절·관측 공백을 확인한다.
- 기존 정상 3대 실제 연결 원본의 **598개 스냅샷을 17,925개 시점으로 재생**했다. 수신 시각에 변동을 넣어도 재생 시간이 뒤로 가지 않고, 차량 간 여유·설비 경계·적재 소유권을 유지하며 종료까지 도달했다. 최소 차량 중심 간 거리는 80.000826이다.
- 기존 이동 검증기의 4,186개 표본에서도 적재 전진·최종 복귀·충돌 여유를 통과했다.
- Chrome에서 실제 기록의 30~55초 구간을 전체 공장→AGV 3인칭으로 재생했다. 카메라 검사 변경 전/후 렌더 콜백 CPU 경과시간 p95는 단회 참고값 **22.9ms→19.8ms**, 최대값 243.2ms→95.2ms였다. 초기 2초는 제외했다. 통제된 성능 비교나 GPU 시간·60FPS 보장으로 해석하지 않는다.
- 테스트 중 기존 5대 수동 장애 실행은 점검 대기 상태로 유지했다. 새로운 연결 생산을 시작하거나 장애를 대신 복구하지 않았다. 변경은 화면 코드에 한정했다.

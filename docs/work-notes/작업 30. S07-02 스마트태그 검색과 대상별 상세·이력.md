# 작업 30. S07-02 스마트태그 검색과 대상별 상세·이력

> 작업 ID: S07-02 · 작업일: 2026-10-05 · 상태: 완료

## 이번 작업은 무엇인가

차체가 많아져도 태그를 입력해 찾고, 지도에서 셀·Bay·차량을 눌러 자세한 정보를 볼 수 있게 했다. 태그·차체 번호뿐 아니라 모델·사양의 일부 문자열로 검색할 수 있고 차체 상태로 목록을 좁힐 수 있다. 현재 전체 보고에서 검색하므로 차체를 새로 등록하거나 별도 상태를 만들지 않는다.

실물 스마트태그 장치를 구현한 것은 아니다. bodyId와 tagId의 1:1 관계를 이용해 해당 차체의 현재 위치, 완료/다음 공정, 예약, 운송, 최종 검사와 관련 보고서를 이어 보는 창이다.

## 기술의 역할

| 구성 | 쉬운 역할 |
|---|---|
| EntityDetails.vue | 선택한 번호의 최신 정보를 현재 전체 묶음에서 찾기 |
| HTML dialog | 상세 창을 띄우고 Escape/닫기/초점 복귀 처리 |
| RecordPanel.vue | 선택 대상의 과거 보고서를 기간과 종류별로 조회하기 |
| REST / cursor | 과거 기록을 제한된 수로 읽고 같은 조회 기준으로 다음 페이지 읽기 |
| ScopedQueries | 예전 실행이나 필터의 늦은 답장이 새 조회를 덮지 못하게 하기 |

## 상세별로 읽는 정보

차체 창은 태그·모델/사양·물리 위치·상태·공정·운송/차량·예약·검사 결과와 관측 시각을 보여 준다. 셀 창은 현재 작업과 남은 시간·차체·배출 차단 원인을 보여 준다. Bay 창은 W/R/A/C와 칸별 차체/예약/운송 번호를 보여 준다. 차량 창은 좌표·현재 적재와 배정된 운송을 구분한다. 픽업 중 배정된 차체가 있어도 실제 적재는 없을 수 있다.

**현재 상세는 SSE의 같은 묶음, 관련 이력은 별도 REST 조회 결과**다. 새 보고가 올 때마다 이력을 다시 조회하지 않는다. 현재 상태의 관측 시각과 이력의 조회 기준을 구분해 표시한다. ‘기록 새로고침’을 누르면 최신 기록을 새 기준으로 읽는다.

차체는 bodyId, 차량은 vehicleId, 셀은 cellId로 이력을 좁힌다. 기존 v1 API에 bufferId 필터가 없으므로 Bay는 ‘연결된 셀의 사건’으로 안내한다. 정확히 그 Bay만의 이력이라고 표현하지 않는다. 사건 내용을 펼쳐 슬롯/예약/운송 번호를 확인할 수 있다.

## 조회 범위와 실제 검증

최근 5분·15분·1시간을 선택하고 한 번에 20건, ‘기록 더 보기’로 최대 100건을 표시한다. 첫 페이지의 기간·필터·cursor 기준을 유지한다. 만료된 cursor는 자동 반복하지 않고 새 조회를 안내한다. cursor는 불투명한 서버 값이며 URLSearchParams로 인코딩한다.

실제 Chrome에서 tag-00003을 검색해 한 대만 표시하고 창을 열었다. 픽업 전 ASM-01/CELL, 이후 AGV-001/VEHICLE로 같은 창이 갱신되는 동안 선택과 이력의 조회 시각을 유지했다. 최종 tag-00001의 HOLD/FAIL과 검사 사건, 페이지 추가/필터를 실제 데이터로 확인했다. 기존 서버 cursor 검증을 반복하지 않고 이번 화면의 요청 범위/지연 응답을 필요한 Node 사례로 확인했다.

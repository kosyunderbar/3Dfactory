# 작업 55. 부품 선보급과 장애 복구 동작 설계

2026-10-11

사용자 요구: 정상 운전에서는 차체가 ASM에 도착하면 부품 때문에 기다리지 않도록 공급한다. 장애 발생 원인과 해결 과정을 관제에 표시하고, 사용자 버튼으로 해결하는 시뮬레이션도 고려한다.

이 문서는 동작 설계안이다. 이번 작업에서는 기존 코드 구조를 확인하고 설계를 기록했으며, 실제 공급·장애 제어와 메인 관제 변경은 구현하지 않았다.

## 확인한 기존 동작

- `model.py`의 `assign_parts()`는 AMR에 키트 운송을 배정한다. 도착한 키트의 공정별 소비·상한 재고·자동 재보급 연결이 필요하다.
- `fail_cell()` / `recover_cell()`은 설비 DOWN 전환과 이전 상태 복원을 지원하지만, 시나리오 기록의 상세 정보는 빈 객체다. 원인·조치·복구 단계·시간·조작 주체 기록을 확장해야 한다.
- `p0_demo.py`는 정해진 단계에 설비 장애와 복구를 호출하는 데모다. 새 사용자 조작형 장애 모드와 혼동하지 않도록 분리한다.

## 정상 부품 공급 제안

- 차체 도착 후 공급을 시작하는 대신, 생산 준비 단계에서 ASM별 키트를 먼저 채운다. 준비 시간과 생산 시간은 구분해서 보여준다.
- 초기 검토값은 ASM별 공급대 용량 2키트. 작업 시작 때 1키트를 소비하고, 사용 가능 재고와 이미 배정·운송 중인 수량을 합산해 부족분만 보충한다. 작업 중인 키트는 공급대 재고와 구분한다.
- 초기 부품 재고를 실제 상태로 명시하거나 AMR으로 선적재한다. 화면에서만 임의 생성하지 않는다.
- 다음 차체 도착 예상 시각, 현재 재고, AMR의 이동·상하차 시간을 고려해 부품 소진이 임박한 공정부터 보급한다. 도착한 차체가 실제로 부품을 기다리는 경우를 우선 처리하고 동률이면 오래된 요청부터 처리한다.
- AMR이 한 번에 한 키트를 운반하는 현재 모델을 기준으로 공급 처리량을 검증한다. 2키트는 확정 용량이 아니며, 지속 공급 능력이 소비 속도보다 낮으면 재고만 늘려 해결됐다고 판단하지 않는다.
- 정상 조건에서 부품 대기 시간 0을 검증 목표로 삼는다. 재고가 없을 때는 실제로 대기해야 하며 순간 이동, 무한 속도, 안전거리 무시로 목표를 맞추지 않는다.

## 장애와 복구 제안

- 기본 정상 운전에는 무작위 장애를 넣지 않는다. 별도 '장애 실험'에서 대상과 원인을 지정한다.
- 첫 범위는 ASM 설비 장애와 부품 보급 지연으로 제한한다. 기존 모델에 없는 AMR 센서 고장·장애물 제거는 별도 확장 대상으로 둔다.
- 자동 복구: 원인 확인 → 시뮬레이션 조치 시간 → 상태 확인 → 재개를 시간 순서로 표시한다.
- 수동 복구: 사용자가 '복구 시작'을 눌러 조치를 시작하고, 같은 조치 시간과 확인 과정을 거쳐 복구한다. 버튼 한 번으로 이력 없이 정상 상태로 바꾸지 않는다.
- 설비 장애 중에는 해당 작업의 진행량과 적재물을 보존하고, 다른 정상 공정은 계속 운전한다. 전체 일시정지·중단과 구분한다.
- 부품 부족은 설비 고장과 구분한다. 실제 배송이 완료돼야 해제되며, '복구 시작'으로 재고를 생성하지 않는다.
- 원인은 주입한 시나리오의 원인이다. 실제 센서로 자동 진단한 결과처럼 표시하지 않는다.
- 이력에는 장애 식별자, 대상, 원인, 영향받은 차체/작업, 발생 시각, 자동/사용자 조치, 조치 내용, 복구 시각과 소요 시간을 기록한다.

## UI 제안과 검증 기준

- 평상시에는 작은 정상 상태 표시만 둔다. 장애 발생 시 공정 라벨에 짧은 원인, 별도 작은 패널에 영향·복구 단계·버튼을 보여준다.
- 예: `ASM-01 · 체결 장치 오류(시뮬레이션)` → `복구 시작` → `장치 재설정 중` → `동작 확인` → `작업 재개`.
- 상세 이력은 펼쳐서 확인한다. 장애 버튼과 로그가 메인 3D 화면을 가리지 않게 한다.
- 정상 연속 생산에서 두 ASM의 공급 부족 대기, 키트 중복 배차·과적·이중 소비를 검증한다.
- 수동 복구 전 장애 유지, 자동 복구 시간 준수, 남은 작업 이어가기, 반복 클릭의 중복 처리 방지, 정상 공정 계속 운전과 이력 일치를 검증한다.
- 후면 AMR 경로를 실제 적용할 때 적재 방향, 회전, 충돌·도킹 간격을 별도로 시뮬레이션한다.

# 작업 42. Windows 로컬 시연과 AGV 재배차 개선

2026-10-06 · S09 이후 로컬 개발·시연 개선 기록

## 실행과 화면

프로젝트 전용 도구와 PostgreSQL, 두 Java 서버, Vite를 PowerShell로 준비·실행한다. Docker 없이 기존 `.env`와 DB를 보존하며 동작한다. [Windows 실행 안내](<../development/Windows Docker 없이 실행.md>)에 설치·빌드·기동·종료 명령과 로그 위치를 정리했다.

Windows 로컬 Vite 화면의 **새로운 공장 실행**에서 1대 정상 생산, 3대 정상 생산, 5대 버퍼·장애·복구·부품 운송을 시작한다. 새 runId로 생성하고 등록 후 자동으로 관측 연결한다. 버튼으로 시작한 자식 프로세스가 진행 중이면 중복 실행을 차단한다. 정적 배포에는 로컬 프로세스 실행 기능이 없다. 버튼과 CLI를 동시에 실행하지 않는다.

정상 생산 3대는 일반 등록과 실제 슬롯·운송·공정 규칙을 사용하며 지정 PASS 검사로 GOOD에 도착한다. 화면은 사용하지 않는 AMR·부품 구역·경로를 숨긴다. 실제 부품 활동이나 AMR 배차 이력이 있으면 표시하며 물리 데이터 자체를 제거하지 않는다. 재조회 시 마지막 스냅샷 시각 기준 24시간의 AMR 배차를 조회한다. 이력 조회 실패 시에는 부품 구역을 표시해 미확인 상태를 미사용으로 단정하지 않는다.

## AGV 배차

기존에는 인계 뒤 시작점 귀환을 완료해 IDLE이 되어야 다음 운송을 맡았다. 현재는 빈 AGV의 IDLE과 RETURNING을 모두 후보로 삼는다. 픽업 지점과 현재 위치의 직선 거리로 가장 가까운 차량을 선택하고 동률이면 vehicleId 순서로 결정한다. 새 배차 검증을 마친 뒤 이전 귀환 경로를 해제하고 현재 위치에서 픽업 경로를 만든다. 이동 중 순간적으로 시작점으로 되돌리지 않는다. 배차할 작업이 없으면 시작점으로 복귀한다.

목적지 슬롯 확보와 차체 소유·예약 규칙은 그대로 적용한다. 픽업/적재/인계에는 모델의 tick 시간이 필요하며 충돌 회피·충전 제어는 구현하지 않는다.

## 5대 시나리오의 의미

**만석을 오류로 발생시키는 시연이 아니라, 용량 초과 배차를 예방하는 보호 동작을 관찰하는 시연**이다. W2/R1/A0에서 신규 배차를 차단하고, 예약된 운송은 진행해 W3/R0/A0로 도착한다. Bay 차체가 셀로 들어가야 슬롯을 반환한다. 반환 후 즉시 새 예약이 잡히면 최종 화면의 A는 다시 0일 수 있다.

BUFFER_FULL은 정상적인 자원 대기다. ASM-01 DOWN/복구는 별도의 의도적인 설비 장애이며 버퍼 만석 때문에 발생한 고장이 아니다. 각 장면의 PAUSED는 관찰을 위한 실행 일시정지다. FAIL 1건은 품질·HOLD 관측을 위한 지정 검사 결과다. 알람 확인은 물리 복구 명령이 아니다.

AGV 이동이 빨라져 FULL_RESERVED 단계를 건너뛰는 것을 막기 위해, P0 드라이버는 첫 두 차체의 도착을 기다린 뒤 세 번째 차체를 ASM-01에 진입시킨다. 이는 시연 투입 순서 조정이며 일반 배차 모델의 제약을 완화하지 않는다.

실행 원본과 결과는 `.build-cache/connected-demo/<runId>`에, 로컬 API 검증 결과는 `.build-cache/windows-dev/improved-verification.json`과 `improved-p0-verification.json`에 남았다. 로컬 파일은 Git 제외 자료다. 이번 결과는 S09의 기존 성능 측정을 갱신하는 근거로 사용하지 않는다. 이번 문서 반영에서는 코드를 변경하거나 공장 시뮬레이션을 다시 실행하지 않았다.

# 작업 53. 상세 설비 전체 적용과 AGV 1인칭 및 관제 UI 정리

2026-10-10

## 요청과 적용

사용자가 작업 52의 AGV·ASM 상세 모델 방향을 승인하고 전체 공장 적용, AGV별 1인칭 시점, 복잡하지 않은 메인 관제 UI를 요청했다.

- ASM-01·02: 승인 모델의 롤러, 고정 클램프, 관절 로봇과 케이블, 제어반, 안전 펜스, 표시등.
- QC-01: 같은 이송 지그 위 검사 게이트, 카메라/조명과 스캐너 표현.
- AGV·AMR: 전후면 조명, 센서, 범퍼, 적재 롤러, 휠, 정비 패널. 차량 번호도 실제 ID를 사용한다.
- 차체: 승인된 차체·팔레트 모델과 검사 결과별 색상. 모델별 도장 재질과 설비 램프를 분리해 다른 객체의 상태에 영향을 주지 않는다.
- Bay·입출고·부품 구역: 슬롯 지지부, 적재 지지대, 부품 선반과 운반 용기.
- 설비 자세와 스캐너는 보고된 작업 상태/시뮬레이션 시각에 연결한다. 보고가 멈추면 동작도 멈춘다.

배차·경로·충돌 규칙·최종 외곽 복귀는 변경하지 않았다. 상세 설비를 기존 장애물 외곽 안에 맞추고, 적재 차량은 기존 원형 안전 영역 안에 들어가게 유지했다. 차체의 셀 적재 높이와 방향을 새 롤러 지그에 맞췄다. 인계 소유권과 위치는 확정 관측값을 따른다. 검토 시안의 고정된 25초 동작을 실시간 생산에 덮어씌우지 않았다.

## AGV 1인칭

3D 화면 위 **차량 시점**에서 AGV-001 또는 AGV-002의 1인칭을 선택한다. 카메라는 차량 전면 +X 방향의 범퍼 앞에 두어 적재 차체가 렌즈를 가리지 않는다. 기존 운동 보간으로 그린 차량과 같은 위치·회전을 사용한다. 상태/목적지/적재 차체/관측 상태는 작은 HUD로 표시한다.

1인칭에서는 화면을 가리는 공장 라벨과 선택 테두리를 숨기고 수동 궤도 회전을 끈다. 전체 공장으로 복귀하면 일반 조작과 라벨 설정이 돌아온다. 차량이 아직 관측되지 않으면 버튼을 비활성화하고, 실행 변경 시 카메라를 초기화한다. 관측 지연·종료 기록에서는 마지막 관측 위치에 정지한다. 실제 영상이나 자율주행 인식 센서 재현은 아니다.

## UI 정리

- 기본 진입 화면은 3D 공장. `?view=2d`는 기존 2D 지도를 연다.
- 큰 소개 문구를 없애고 상단을 공장/차체 조회/품질·알람/기록 탭으로 구성했다.
- 실행 선택과 시나리오·시작·중단을 한 줄에 배치했다. 실행 중인 시뮬레이션과 다른 기록을 볼 때 현재 실행 복귀 버튼을 표시한다.
- 생산 요약은 작은 숫자 4개로 정리하고, 공장 오른쪽에 설비/차량 상태를 모았다.
- 차체 검색은 별도 탭으로 옮겼다. 연결 진단과 실행 ID는 펼침 영역에 보존했다.
- 연결/관측 상태는 항상 상단에 남겨 실시간 값과 종료·지연 값을 구분한다. 관측 부재는 0으로 추정하지 않는다.
- 작은 화면에서는 조작부가 줄바꿈되고 현황 패널이 지도 아래로 이동한다. 이번 브라우저 검증은 현재 데스크톱 크기에서 수행했다.

## 검증

- `scripts/console.sh build` 성공. Three.js/ECharts의 기존 대형 청크 경고는 남아 있다.
- `scripts/console.sh test`: 18개 통과. 카메라 방향/렌즈 위치, 작업·대기 자세에서 설비 영역 준수, 적재 차량의 회전 안전 영역, 재질 상태 분리를 포함한다. 로컬 포트가 필요한 launcher 테스트는 포트 제한 밖에서 실행했다.
- Chrome에서 실제 3대 정상 생산을 시작했다. AGV-001 적재 운반, AGV-002 픽업 이동, 차량 전환, 전체 시점 복귀, 외곽 복귀와 종료 화면을 확인했다.
- 차체 검색과 상세 이력, 품질 조회, 기록 조회, 2D/3D 전환, 다른 실행 선택 시 카메라 초기화와 현재 실행 복귀를 확인했다.
- 초기 그림자 옵션의 Three.js 경고를 현재 지원하는 PCF 옵션으로 수정했다. 최종 배포본 브라우저 오류/경고 없음.

# 작업 59. 정상 1대·3대와 장애 5대 수동 복구 시나리오 정정

2026-10-11

사용자가 작업 58의 해석을 정정했다. 수동 복구 **방식**을 기준으로 삼으라는 의미이며, 장애 시나리오의 투입 수량은 5대여야 한다.

## 최종 구성

1. 1대 · 정상 생산
2. 3대 · 정상 생산
3. 5대 · 장애 / 수동 복구 (기본 선택)

화면의 이름뿐 아니라 `--connected-maintenance-demo`의 실제 등록 차체 수를 5대로 바꿨다. `NormalDriver`는 1/3/5대 생산을 지원한다. 정상 1대/3대에는 장애 제어기를 적용하지 않고, 5대 장애 시나리오에는 기존 ManualMaintenance를 연결한다.

장애 발생 → 사용자 현장 점검 시작 → 사용자 조치 완료 → 2초 동작 확인 → 보존된 작업 재개. 사용자 입력 없이 자동으로 복구하지 않는다. AMR 실제 선보급·재고 소비, AGV 충돌 규칙 및 최종 외곽 복귀를 유지한다. 5대 생산의 실행 제한은 900초이며 사용자 점검 대기 시간은 기존과 같이 제한 시간에서 제외한다.

과거 실행 기록의 투입 대수를 소급해서 변경하지 않는다. 기존 P0 자동 검증 CLI는 개발 검증용으로만 남아 있으며 일반 웹 선택지는 위 세 가지다.

## 검증

- 실제 CLI 플래그의 1대 정상 / 3대 정상 / 5대 수동 복구 매핑을 테스트한다.
- 5대 + 후면 AMR + 수동 복구 오프라인 시뮬레이션에서 15개 공정 작업 완료, 모두 PASS, 전 차량 복귀 확인.
- 5대 장애 중 부품 중복 소비와 과잉 재고가 없고, ASM별 5키트 소비·초기 2 + AMR 보급 3, 총 6회 보급, 부품 대기 0ms 확인.
- Python 전체 58개 테스트 통과. 웹 빌드 성공. 웹 컨테이너 갱신.
- 웹에서 새 실행 `run-20261010-396b97224d804ae7b871e640e2fdf541`을 시작해 실제 5대 투입 및 수동 장애 대기 화면을 확인했다. ASM-01의 22.7초 장애 발생 후 자동 복구 없이 점검 대기를 유지한다. 사용자가 직접 조작할 수 있도록 현장 점검 시작 버튼을 보이는 상태로 열어 두었다.

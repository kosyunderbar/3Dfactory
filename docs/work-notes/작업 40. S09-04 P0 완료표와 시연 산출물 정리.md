# 작업 40. S09-04 P0 완료표와 시연 산출물 정리

> 작업 ID: S09-04 · 2026-10-05 · 완료 · 제출 자료: [S09 측정·완료 기록](<../development/S09 측정·완료 기록.md>)

이번 작업은 지금까지 만든 기능, 실제 확인한 결과, 남아 있는 범위를 한곳에 정리합니다. 파일이 있다는 이유로 기능이나 성능을 완료했다고 설명하지 않습니다.

## P0 완료표

독립 서비스와 DB 소유, 원본·outbox 저장, 업무 멱등 처리, REST/SSE 전체 상태 연결, 가상 스마트태그, 차체 운송·예약·만석·반환, 검사 집계, 알람 확인/복구, 장애 복구의 근거를 연결합니다.

변경 없는 기능은 해당 단계의 검증 결과를 재사용합니다. S09에서 모든 테스트를 다시 돌린 것처럼 쓰지 않습니다. 새 실행의 정상·만석·복구는 별도 시연 원본과 실제 브라우저 증거로 남깁니다.

## 기능 완료와 성능 결과

부하 측정을 수행했다는 사실과 성능 목표를 달성했다는 사실은 다릅니다. 정상·스트레스의 실제 입력량, 지연, 대기량과 SQL·화면 비용을 그대로 기록합니다. 못 만든 입력 목표나 부족한 화면 조건도 함께 표시합니다.

차체 100대의 정상 흐름을 확인한 기존 결과는 AGV 수백 대의 처리 성능을 뜻하지 않습니다. P0 차량은 AGV 2대·AMR 1대입니다. 가상 태그는 차체 정보에 접근하는 식별자이며 실제 무선 장치는 구현하지 않습니다.

## 캡처와 영상

새 시연의 같은 runId를 유지한 실제 화면을 저장합니다. 단계의 캡처와 캡처를 순서대로 재생하는 영상은 연속 실시간 녹화와 구분해 표시합니다. 원본 이미지, 순서·시각·단계 설명, 재생 자료를 함께 제공합니다.

## 설계 결정을 남기는 이유

왜 두 서비스로 나눴는지, 왜 ACK와 업무 반영을 구분했는지, 왜 예약을 이동 중에도 슬롯 사용으로 세는지 설명합니다. 나중에 기능을 확장할 때 기존 규칙을 잊고 서로 모순되는 계산을 추가하지 않도록 합니다.

`W + R ≥ C`일 때 신규 배출을 막는 규칙은 예약 없는 배출과 목적지 초과 진입을 막습니다. 모든 복잡한 경로·차량 교통·자원 사이클에 대한 교착 상태 부재를 수학적으로 증명한 것은 아닙니다. 최종 설계 결정과 후속 범위는 완료 기록에 연결합니다.

## 이번 실제 결과와 자료

# 작업 29. S07-01 실제 공장 SVG 지도와 차량·슬롯

> 작업 ID: S07-01 · 작업일: 2026-10-05 · 상태: 완료

## 이번 작업은 무엇인가

기존 셀 카드 옆에 실제 공장의 지도를 붙였다. **Python이 결정한 셀·차체·차량·Bay 상태를 Vue가 같은 보고서로 표시한다.** 작업 셀 3개, 차체 AGV 2대, 부품 AMR 1대와 Bay의 칸을 볼 수 있다. 독립 HTML 샘플은 기존 참고 자료로 유지한다.

지도는 배차를 승인하거나 차체를 옮기지 않는다. 서버의 layout 조회는 장소와 경로의 고정 배치를 알려 주고, REST/SSE 전체 묶음은 현재 위치와 상태를 알려 준다. 고정 지도와 현재 보고를 합쳐 그리는 역할이다.

## 기술의 역할

| 구성 | 쉬운 역할 |
|---|---|
| SVG / FactoryMap.vue | 좌표 위에 셀·경로·슬롯·차량을 그리는 확대 가능한 그림 |
| layout REST | 해당 실행의 장소, 경로, 좌표 읽기 |
| ConsoleFeed / 전체 SSE 묶음 | 셀·차체·슬롯·차량을 같은 시점으로 갱신하기 |
| presentation.js | 보고서의 코드 이름을 화면 이름으로 바꾸고 지도에 연결하기 |
| CSS | 흰색·네이비·파란색과 실선/점선·상태 이름으로 구분하기 |

## 무엇이 화면에서 구분되는가

차체 경로는 실선, 부품 경로는 점선이다. Bay는 여유·예약·대기를 칸마다 표시하고, 만석은 점선 테두리와 W/R/A 숫자로 표시한다. 고장 난 셀에는 ‘설비 정지’, 배출이 막힌 셀에는 ‘배출 대기’와 원인이 표시된다.

예약된 차체는 픽업 전까지 앞 셀에 남는다. 이때 AGV는 ‘픽업 이동 / 실제 적재 없음’이다. 배차의 bodyId를 실제 적재로 표시하지 않는다. Python의 적재 시작 보고가 들어오면 차체 위치가 VEHICLE로 바뀌고 차량의 실제 cargo를 표시한다. 부품 AMR은 partsKitId를 표시하며 차체 Bay 슬롯을 소비하지 않는다.

차량 그림은 새로 보고된 좌표로 갱신한다. 보고 사이의 위치를 예상해 계속 움직이는 보간을 넣지 않았다. 연결이 끊기면 마지막 좌표와 상태를 보존한다. 선택 상세도 같은 전체 묶음을 읽으므로 지도와 따로 이동하지 않는다.

## 실제 사례와 최소 검증

명시적 `--connected-p0-demo`는 빈 공장에 정상 등록한 차체 5대와 부품 kit로 출발한다. ASM-02의 진입을 잠시 기다려 **W2/R1/A0 → W3/R0/A0 → Bay에서 셀 진입 후 W2/R0/A1**을 만든다. 도착은 예약을 대기로 바꿀 뿐 슬롯을 반환하지 않는다. 셀 진입이 실제 반환이다. 해당 상태를 Python 원본, 두 DB, REST, 프록시 SSE와 실제 Chrome 지도/상세에서 대조했다.

새 자동 검증은 지도 데이터 경계 1개와 P0 정상 등록 시나리오 1개를 공유한다. 별도의 그림 구조/색상 테스트는 추가하지 않았다. 자세한 실제 실행 번호·원본 수·캡처는 [공유 검증 기록](<../validation/최소 검증 시나리오와 도구.md>)을 따른다.

## 실행과 다음 범위

```sh
INGESTION_TCP_HOST=127.0.0.1 INGESTION_TCP_PORT=9090 scripts/simulator.sh run --connected-p0-demo
```

이 명령은 실제 두 DB에 새 실행을 남긴다. 콘솔에 나온 runId를 관제 화면에서 선택한다. 일반 컨테이너 기동은 자동 생산하지 않는다. 수백 대 차량의 지도 비용과 성능 측정은 후속이며 이번 결과를 확대한 성과로 쓰지 않는다.

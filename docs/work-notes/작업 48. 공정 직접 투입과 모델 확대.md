# 작업 48. 공정 직접 투입과 모델 확대

2026-10-10 · BAY에 내려놓아야 할 때만 방문, AGV 상태 글자 축소, 3D 모델 확대

## 동작

- 새 교통 실행을 정책 2로 구분했다. traffic 없는 실행과 정책 1의 기존 기록·배치·운송 규칙은 보존한다.
- 빈 정상 설비에는 AGV가 CELL 접안 위치로 직접 운반한다. 적재·하차 후에만 차체 소유를 CELL로 바꾸고 작업을 시작한다. 회수도 같은 CELL 접안 위치에서 한다.
- 설비가 사용 중·고장·입고 예약 상태이거나 앞선 Bay 대기가 있으면 Bay 슬롯을 예약한다. Bay 대기 차체도 별도 AGV 운송으로 설비에 넣는다. Bay→설비 순간 이동을 제거했다.
- 활성 CELL행 운송은 해당 설비의 입고 예약으로 취급해 중복 투입을 막는다. 이동 도중 설비가 고장 나면 차량이 차체를 보유하고 복구 후 인계한다.
- 적재 직전에 설비 상태를 다시 확인한다. 그동안 설비가 비었으면 기존 Bay행 운송을 DIRECT_DELIVERY_AVAILABLE 사유로 취소·슬롯 반환하고 CELL행 운송을 새로 배정한다.
- Bay 슬롯은 차체를 AGV에 싣는 순간 BODY_PICKED_UP 사유로 반환한다. 기존 입고 운송·예약을 참조한다. 직접 CELL 인계 사건의 bufferId/slotId는 null이다. 실제 운송 이력이 있는 경우만 관제에서 허용한다.
- P0 5대 시나리오는 ASM-02를 고장 상태로 두어 실제 Bay 대기를 유도하고, 복구 후 AGV가 슬롯의 차체를 픽업한 시점에 슬롯 반환 단계를 관측한다.

- 차량 반경 24→30, 차량 간 최소 중심 간격 51→63. 설비·Bay 충돌 영역, 접안 여유, 부품 구역, 경계와 주차 위치를 함께 조정했다.

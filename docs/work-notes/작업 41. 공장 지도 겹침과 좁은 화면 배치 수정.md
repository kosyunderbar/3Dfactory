# 작업 41. 공장 지도 겹침과 좁은 화면 배치 수정

> 작업일: 2026-10-06 · 상태: 완료 · S09 이후 화면 수정

## 어떤 문제를 고쳤는가

같은 BODY-IN 위치에서 대기하는 AGV 두 대를 같은 좌표에 그려 차량 그림이 서로 가렸다. 차량 이름은 구역 이름과 겹쳤고, GOOD에 도착한 차체도 같은 자리에 쌓여 마지막 한 대의 번호만 보였다. Bay 슬롯의 마지막 줄은 카드 아래쪽 여백이 부족했다.

보고 내용이 틀린 문제와 화면을 읽기 어려운 문제를 구분해야 한다. 차량 두 대가 같은 장소를 보고하는 것은 정상일 수 있다. 그래서 공장의 좌표를 바꾸는 대신 **그 정보를 화면에 배치하는 방법**을 수정했다.

## 무엇이 달라졌는가

- 차량마다 이름·상태·실제 적재 정보를 담은 카드를 따로 표시한다. 같은 위치에 있어도 각 차량을 선택할 수 있다.
- 카드가 셀·Bay·구역 이름과 겹치면 빈 공간으로 옮긴다. **연결선 끝의 점이 실제 보고 위치**이고, 카드가 있는 곳을 새 물리 위치로 해석하지 않는다.
- BODY-IN/GOOD/HOLD는 현재 차체 총수와 최대 네 대의 개별 번호를 표시한다. 더 많으면 나머지 대수를 안내한다. 전체 차체는 기존 스마트태그 검색에서 조회한다.
- 셀, 운반 경로, Bay, 부품 인계 구역 사이의 간격과 글자 크기를 조정했다. 슬롯은 마지막 줄까지 카드 안에 들어간다. W/R/A에 전체 용량 C도 함께 표시한다.
- 관제 화면의 최대 폭을 넓혔다. 작은 화면에서는 지도 내부를 스크롤하며, 차체 카드와 검색 입력은 화면 폭에 맞춰 줄어든다.

흰색·네이비·파란색 기준과 Java/Python/Vue/PostgreSQL 기술 스택을 유지했다. 새로운 의존성은 추가하지 않았다.

## 파일들의 역할을 쉽게 설명하면

| 파일 | 역할 |
|---|---|
| `src/presentation.js` | 보고서의 셀·슬롯·차체·차량을 같은 시점으로 연결하는 기존 데이터 준비 |
| `src/map-layout.js` | 이름표와 카드가 놓일 빈 공간을 찾는 새 화면 배치 함수 |
| `src/components/FactoryMap.vue` | 배치 결과를 SVG 그림과 클릭 가능한 대상으로 표시 |
| `src/style.css` | 글자 크기·테두리·간격·좁은 화면의 크기 조정 |

`map-layout.js`의 배치 좌표는 이름표를 놓는 자리다. 원본 `vehicle.position`, 차체의 `locationId`, 실제 적재, 슬롯 소유자와 W/R/A/C는 변경하지 않는다. 보고 사이에 이동을 추정하거나 새 배차를 승인하지도 않는다. 셀 안의 차체는 셀 카드에 표시하고, 셀 상세에서 차체 상세로 이동할 수 있다.

## 꼭 필요한 확인과 결과

1. **빌드와 기존 Node 테스트 5개:** 통과했다. 화면 컴파일, 기존 동일 시점 데이터·조회 범위·연결 상태 처리를 확인했다. 새 테스트 프레임워크나 반복용 테스트 파일은 추가하지 않았다. 좁은 화면 CSS를 추가 반영한 최종 Compose 빌드도 통과했다.
2. **배치 확인 10가지:** 구역에 차체 5대/100대가 모인 경우와 차량들이 동일한 다섯 경로 좌표에 있는 경우를 조합했다. 카드 겹침·화면 범위 밖 잘림·보고서 변경은 0이었다. 전체 차체 대수와 차량 식별자를 보존했다. 합성 데이터로 배치 함수만 확인했으며, 100대 실제 공장 실행이나 성능 측정 결과로 사용하지 않는다.
3. **현재 실제 Chrome 화면:** 기존 종료 실행 `run-20261005-35a179e5de144d0289c41d53da9f40ec`를 그대로 관측했다. 지도 글자 47개의 영역을 비교해 겹침 0을 확인했다. AGV-001 상세의 보고 좌표 `0.0, 100.0`과 실제 적재 없음, GOOD의 tag-00005 상세의 GOOD/PASS를 확인했다.
4. **실제 화면 폭 390px:** 페이지 전체의 가로 넘침이 없고, 지도 자체에만 가로 스크롤이 생겼다. 글자 겹침은 0이었으며 AGV-002 상세를 열고 닫을 수 있었다. 임시 화면 크기 설정은 확인 뒤 해제했다.

수정한 `factory-console` 컨테이너만 다시 빌드·기동해 현재 화면에 반영했다. DB·수집·관제·시뮬레이터 서비스는 재기동하지 않았고, 새 제조 실행이나 데이터 삭제도 수행하지 않았다. 전체 부하·장애 검증은 반복하지 않았다. 기존 품질 차트 번들의 크기 경고는 남아 있다.

## 다른 컴퓨터에서 수정 화면을 반영하려면

clone한 소스가 최신이면 최초 `up`에서 함께 빌드된다. 이미 실행 중인 환경은 프로젝트 루트에서 화면만 다시 빌드한다.

```sh
scripts/dev-stack.sh compose up -d --build --wait --no-deps factory-console
```

그다음 브라우저를 새로고침한다. 현재 실행 ID의 상태와 이력은 유지된다. 예전 S07/S09 캡처와 영상은 당시 증거로 보존하므로 최신 화면과 배치가 다를 수 있다.

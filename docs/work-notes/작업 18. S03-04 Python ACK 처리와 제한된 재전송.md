# 작업 18. S03-04 Python ACK 처리와 제한된 재전송

> 작업 ID: S03-04 · 완료일: 2026-10-05 · 상태: 완료  
> Python 3.12 표준 라이브러리만 사용 · ACK는 수집 저장 확인

Python이 “보냈다”는 이유만으로 보고서를 지우지 않도록 구현했다. 서버가 저장하고도 ACK가 통신 중 사라질 수 있기 때문이다. 미확인 원본을 보관했다가 같은 바이트와 번호로 다시 보내고, 해당 원본의 저장을 확인한 ACK를 받았을 때만 제거한다.

## 송신 담당 코드

[sender.py](../../services/factory-simulator/factory_simulator/sender.py)의 Original은 최초 UTF-8/LF 프레임과 식별자·SHA-256을 보관한다. PendingQueue는 미확인 목록, Sender는 소켓 송신/ACK 확인/재시도, SourceSession은 공장 모델 변경과 목록의 용량을 연결한다. 공장 계산 코드는 기존 model.py에 남아 있다.

송신 창은 1건이다. 목록의 맨 앞 사건을 확인하기 전 뒤 순번을 보내지 않는다. 성공 ACK의 version/kind·네 번호·해시·상태/코드·시각 필드가 맞아야 제거한다. RECEIVED와 DUPLICATE_RECEIVED는 둘 다 저장 확인이다. 깨진 답장이나 다른 번호/해시의 답장은 성공으로 해석하지 않는다.

접속 제한은 2초, ACK 대기는 3초다. 처음 송신을 포함해 최대 10회 시도한다. 재시도 간격은 500ms부터 두 배씩 증가하고 최대 30초, 양의 jitter는 0~10%다. 서버의 유효한 retryAfterMs가 더 길면 그 값을 따른다. 30초를 넘는 잘못된 재시도 설정은 PAUSED_CONFIG다.

영구 거절은 오류 로그와 함께 STOPPED_REJECTED로 멈춘다. 자동으로 내용을 고치거나 새 ID를 붙이지 않는다. 10회 소진은 PAUSED_RETRY이며 같은 원본이 head에 남는다. 명시적인 Sender.resume()은 같은 원본으로 다시 시도하게 한다. 영구 거절 run은 이 방법으로 재개하지 않는다. 로컬 오류 로그도 10MiB씩 최대 3개다.

## 대기 목록이 차면 공장도 멈추는 연결

미확인 목록은 최대 1,000건·64MiB다. LF를 포함한 프레임 바이트를 세므로 원본만 세는 것보다 조금 보수적이다. 900건 또는 60MiB에서 미리 멈추며, 100건·4MiB의 여유를 PAUSED 제어 사건에 남긴다.

SourceSession을 붙인 모델 변경은 물리 상태와 사건을 잠시 준비한 뒤, 그 사건 묶음이 미확인 목록에 들어갈 수 있는지 확인한다. 묶음 전체가 들어가지 못하면 그 변경의 시간·작업·차체/슬롯·번호·사건을 함께 되돌리고 RUN_STATE_CHANGED(PAUSED)만 기록한다. 일단 완료한 tick을 목록에서 일부 버리는 방식이 아니다. 멈춘 동안 session.tick/change는 새 공정·계속된 스냅샷을 만들지 않는다.

자동 용량 정지는 목록이 500건 미만이고 32MiB 미만이며 송신 상태가 READY일 때만 풀 수 있다. 작업자가 SourceSession.pause()로 정지하면 자동으로 풀지 않는다. 실패한 head로 송신이 멈춘 경우에는 송신 재개와 공장 재개를 명시적으로 결정한다.

저장 확인된 사건은 모델 저널에서도 메모리를 해제한다. 다음 sourceSeq는 별도로 유지하므로 저널을 줄여도 번호를 재사용하지 않고, RUN_FINISHED의 uniqueEventCount도 유지한다. SourceSession을 붙이지 않은 기존 오프라인 데모는 종전처럼 로컬 전체 사건을 읽을 수 있다.

## 실행 방법

수집 서버가 기동한 상태에서 준비된 NDJSON 파일의 원본을 명시적으로 보낼 수 있다. 경로는 절대 경로를 사용한다.

```sh
INGESTION_TCP_HOST=127.0.0.1 INGESTION_TCP_PORT=9090 \
  scripts/simulator.sh run --send-events /absolute/path/events.ndjson
```

파일은 한 프레임씩 읽고 저장 ACK를 기다린다. 성공 출력은 INGESTION_CONFIRMED이며 operationsApplied/guiLive는 false다. 실패하면 종료 코드 2이고 원본 파일은 남는다. 같은 파일을 명시적으로 다시 보내면 이미 맡은 원본은 중복 ACK로 확인한다. 사건 목록 JSON 배열과 선행 등록이 생략된 계약 예제는 실제 공장 실행 이력 파일로 간주하지 않는다.

일반 컨테이너 기동은 여전히 MODEL_INITIALIZED와 heartbeat다. 이번 작업에서 공장 생산을 자동 시작하지 않았다. SourceSession의 실제 연결 흐름은 다음 최소 검증 명령으로 재현한다.

```sh
# 전체 Compose 환경이 준비되어 있을 때 실행
python3 scripts/verify-ingestion-source.py
# Python 코드의 변경 경계만 확인
PYTHONPATH=services/factory-simulator .build-cache/simulator-venv/bin/python \
  -m unittest discover -s services/factory-simulator/tests -p test_sender.py -v
```

새 송신 테스트는 3개다. ACK 유실/깨짐/상관관계 오류에서 같은 원본 재송신·1건 창, 최대 시도/재시도 지연/거절 시 head 보존, 건수·바이트 제한/실제 완료 tick rollback/제어 정지/안전한 재개/의도한 정지 보존을 묶어 확인했다. 모델 저널의 순번 처리가 바뀌어 영향받는 기존 Python 테스트까지 한 차례 실행했고 총 20개가 통과했다. 이후 정지 우선권 수정은 송신 테스트 3개만 다시 확인했다.

실제 연결에서는 39건의 원본과 저장 ACK, 재접속 중복 확인, DB 원본 바이트/해시 일치, 미확인 목록 0건과 확인된 모델 저널 해제을 확인했다. 작업 17의 연결 증거를 공유한다.

## 보장 범위

미확인 목록은 P0에서 메모리다. Python 프로세스 자체가 종료되면 모델/목록을 영속 복원한다고 보장하지 않는다. 새 실행은 새 run을 사용한다. 원본 파일의 명시적 재송신은 저장 이력을 다시 확인하는 기능이며 공장의 물리 상태 복원을 뜻하지 않는다. 서버 재시작/네트워크 단절 시 살아 있는 Python의 원본 유지와 제한된 재접속을 지원한다.

# 작업 50. AGV 동선 효율 복구와 시뮬레이션 중단

2026-10-10

## 사용자 피드백과 원인

정책 3 적용 후 회전과 우회가 늘고, 인계한 차량이 멀리 돌아가 비효율적이라는 피드백을 받았다. 앞선 검증은 충돌·완료 여부를 확인했지만 실제 이동거리·회전량·현장 대기 효율을 충분히 평가하지 못했다. 일방통행 순환, 매 인계 뒤 먼 초기 주차장 복귀, 직선 중간 노드 정차, 짧은 접안 출구의 180도 회전이 주된 원인이었다.

## 변경

새 실행 기본값을 정책 4로 구분한다. 정책 1~3과 기존 기록은 보존한다.

- 양방향 통로에서 A*로 계획하고 예약으로 대향·교차 통행을 제어한다.
- 같은 직선의 중간 노드를 병합해 연속 주행한다. 회전/목적지에서는 감속·정차한다.
- 길이 100 이하 구간은 필요하면 차체 방향을 유지한 채 최고 속도 절반으로 후진한다. 화면도 이동 벡터 대신 보고된 차체 heading으로 회전한다.
- 셀 인계 후 남은 공정 시간이 8초 이하면 현장 대기 후 완료 차체를 픽업한다. 고장/긴 공정은 이 대기 예약에서 제외한다.
- 출고 접안점은 차량별 인근 대기점으로 비운다. 나머지 현장 대기는 다른 배정 차량의 목적지를 막는 경우에만 이동한다.
- 현장 대기 라벨은 `완료 대기 · ASM-01` 등으로 표시한다. 짧은 대기점 이동을 먼 기지 복귀로 표시하지 않는다.
- P0는 W+R=C인 ASSIGNED 운송을 추적해 만석 예약→운송 중 장면을 관측한다. 빠른 연속 운송에서 앞선 모든 차체의 도착만 기다리다가 관측 단계를 놓치던 조건을 고쳤다.

## 중단 버튼

개발 관제의 시작 버튼 옆 `시뮬레이션 중단`을 추가했다. 동일 출처 JSON 요청과 현재 runId를 검증한 뒤 이 실행기가 소유한 Python 자식 프로세스에만 SIGTERM을 보낸다. 임의 PID/명령은 받지 않는다. STOPPING 동안 중복 시작을 막고, 실제 종료 후 STOPPED로 표시한다. 반복 중단은 중복 신호를 보내지 않는다. 관측 기록과 원본은 보존한다.

이는 일시정지/이어하기가 아니다. 새 시작은 별도 실행이다. 중단을 생산 완료로 위장하지 않으므로 DB의 마지막 RUNNING 스냅샷은 그대로 남고 이후 소스 비연결 상태로 보인다. 실행기 배너에서 사용자 중단을 별도로 알려준다. 정적 관제 서버에는 프로세스 실행기가 없으며 버튼은 실행기 환경을 갖춘 개발 서버에서 제공한다.

## 같은 조건 비교

100ms tick, 같은 공장 설정과 품질 결과열로 정책 3/4를 비교했다. 시간은 오프라인 모델 시간이며 네트워크 지연·P0 장면 관찰 대기를 포함하지 않는다. 거리는 모델 좌표 단위, 회전량은 모든 차량의 절대 회전 합이다.

| 시나리오 | 항목 | 정책 3 | 정책 4 |
|---|---|---:|---:|
| 정상 3대 | 완료 시간 | 346.5초 | 210.2초 |
| 정상 3대 | 이동거리 | 15,520 | 7,460 |
| 정상 3대 | 회전량 | 12,420° | 4,140° |
| P0 5대 | 완료 시간 | 806.0초 | 445.2초 |
| P0 5대 | 이동거리 | 35,860 | 16,530 |

정상 3대에서 시간 39.3%, 거리 51.9%, 회전량 66.7% 감소. P0는 검사 순서가 달라져 개별 차체의 PASS/FAIL 배정은 다르지만 같은 결과열로 PASS 2대/FAIL 3대가 모두 GOOD/HOLD에 도착했다. 최소 차량 중심 간 거리는 양 시나리오 모두 80으로 기준 63 이상이다. 정상에서도 교통 양보가 3번 남아 있으며 모든 우회가 사라졌다는 뜻은 아니다.

## 범위

현재 공장의 평면 운동과 통행 제어를 개선했다. 강체 충격·타이어 접지·센서 인식 모델은 아니며 임의 공장 배치의 최적성/무교착을 보장하지 않는다. 구간 예약과 정차 회전은 안전을 위해 유지한다. 기존 실행 기록을 재계산하거나 지우지 않는다.

## 실제 연결 실행 최종 결과

`run-20261010-17e3fdbfd8ea4307a84b90f7f13776a9`는 정책 4로 정상 3대 생산을 마쳤다. 517개 사건의 원본 바이트·순번·SHA-256이 Python 기록, ingestion DB, operations DB에서 모두 일치했다. 전달 대기는 0건, 관제 상태는 FINISHED, 세 차체는 모두 GOOD/PASS다. 실제 연결 스냅샷도 화면 보간 검증을 통과했다. `lane-v4-connected-verification.json`과 `lane-v4-connected-render-verification.json`에 결과를 보존한다. 화면 새로고침 뒤에도 실행 중인 시나리오 선택값을 실행기의 실제 값으로 복구한다.

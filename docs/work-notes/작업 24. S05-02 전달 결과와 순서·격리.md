# 작업 24. S05-02 전달 결과와 순서·격리

> 작업 ID: S05-02 · 완료일: 2026-10-05 · 상태: 완료

## 이번 작업은 무엇인가

관제의 답장을 보고 계속 진행할지, 다시 보낼지, 문제 보고서를 보존하고 멈출지 결정했다. 단순히 HTTP 연결이 됐다는 이유로 성공 처리하면 안 된다. 답장의 버전·실행/송신원/사건 번호·순번·원본 해시와 상태를 함께 확인한다.

## 답장에 따른 처리

| 상황 | 수집기의 처리 | 다음 순번 |
|---|---|---|
| APPLIED / DUPLICATE_APPLIED | DELIVERED와 책갈피 증가를 함께 저장 | 진행 |
| 연결 오류·timeout·응답 유실·일시 5xx | 원본 보존, 간격을 늘려 제한 재시도 | 대기 |
| 선행 실행/참조 미확인 | 최초 오류부터 최대 30초 대기 후 PAUSED_DEPENDENCY | 대기 |
| 기대 순번 없음 | GAP_WAIT, 30초 뒤 PAUSED_GAP | 누락 원본 도착 때 그 번호부터 진행 |
| 20회 자동 시도 소진 | PAUSED_RETRY | 원인 해결 뒤 명시적 재개 |
| 영구 업무 모순·ID 충돌 | 해당 원본 QUARANTINED + 실행 BLOCKED | 진행 금지 |
| 경로/규격 오류·답장 번호/해시 불일치 | PAUSED_CONFIG | 설정 해결 뒤 같은 원본 재개 |
| 관제의 RUN_BLOCKED | 실행 BLOCKED, 아직 처리하지 못한 원본 유지 | 진행 금지 |

QUARANTINED는 문제 원본을 별도 상태로 보관한다는 뜻이다. 해당 원본과 거절 답장·코드·시각·횟수는 DB에 남는다. BLOCKED는 그 실행의 뒤 순번도 자동으로 보내지 않는다는 뜻이다. 두 상태 변경은 한 트랜잭션이며 책갈피는 그대로다. 다른 실행은 계속 진행한다.

RUN_BLOCKED 답장은 해당 보고서 자체가 영구 거절됐다는 증거가 아니다. 따라서 이 경우 아직 처리하지 못한 사건을 임의로 QUARANTINED라고 표시하지 않는다. 기존 원본의 상태와 중단 이유를 구분해 보관한다.

## 응답을 못 받았는데 관제에 이미 저장됐다면

검사 보고서 10번을 관제가 저장했지만 답장이 유실됐다고 해 보자. 수집기는 성공을 확정하지 못해 10번을 다시 보낸다. 관제는 같은 번호·원본을 확인하고 DUPLICATE_APPLIED라고 답한다. 검사 수는 한 번만 증가한다.

관제 답장을 받은 뒤 수집기의 완료 저장이 실패해도 마찬가지다. outbox 완료 표시와 다음 순번이 함께 rollback되므로 10번이 계속 head다. 재시도 뒤 중복 성공으로 전달 장부를 완료한다. 이것은 **재전달을 허용하면서 업무 중복 반영을 막는 구조**이며 전체 통신을 무조건 exactly-once라고 표현하지 않는다.

## 순서를 지키는 이유

차체 등록 보고서보다 해당 차체의 검사 보고서를 먼저 처리하면 참조가 없다. 정상 경로는 실행별 nextSourceSeq 한 건씩 전달한다. 최대 수신 순번이나 DB 행 ID가 높다는 이유로 앞 보고서를 건너뛰지 않는다. 앞 보고서의 실패가 다른 실행 전체를 멈추게 하지도 않는다.

차체 Bay의 W+R≥C 판단은 계속 Python 모델이 맡는다. 전달 장애를 이유로 이미 예약한 슬롯을 풀거나 차체를 다시 배출하지 않는다.

## 꼭 필요한 검증 결과

작업 23~25의 공유 검증 8개 안에서 다음을 실제 PostgreSQL과 HTTP로 확인했다.

- 관제 커밋 후 깨진 응답을 주입하고 재전달해 업무 한 건만 보존했다.
- 수집 완료 저장 중 실제 SQL 제약 실패를 주입해 완료/책갈피 동시 rollback과 다음 재전달을 확인했다.
- 별도 검증 클러스터의 관제 DB 접속을 잠시 차단한 뒤 복구해 원본 유지와 중복 없는 진행을 확인했다.
- 순번 누락 30초 보류 후 원본 도착, 의존성 30초 보류, 관제 영구 거절/격리와 다른 실행 진행을 확인했다.
- 20회 한도와 재시작 후 보류 유지, 재개 뒤 같은 원본의 완료를 확인했다.

첫 검증의 실패는 시험 runId 날짜에 붙은 Z 때문이었다. 시험 입력을 날짜 형식에 맞게 고친 뒤 같은 필요한 묶음 8개가 통과했다. Python/관제/GUI 전체 테스트를 다시 실행하지 않았다.

## 남은 작업

격리된 원본의 payload 수정·자동 건너뛰기·BLOCKED 강제 해제는 제공하지 않는다. 영구 모순을 수정한 시연은 새 run으로 시작한다. 이미 지나간 순번 범위의 수동 재전달 도구와 여러 전달 인스턴스 운영은 이번 범위 밖이다.

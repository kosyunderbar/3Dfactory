# 작업 56. 사용자 점검과 조치 완료를 기다리는 수동 복구

2026-10-11

사용자 요구: 오류를 관제에서 발견하고 엔지니어가 현장에 가서 해결하는 느낌의 수동 복구.

## 구현

- 개발 관제의 기본 선택 시나리오를 `3대 · 수동 장애 복구`로 변경했다. 정상 1대/3대는 그대로 선택 가능하다. 기존 자동 단계 진행 P0는 `5대 · 자동 복구 검증 데모`라고 구분한다.
- 첫 ASM-01 조립의 실제 작업 진행량이 1초에 도달하면 `체결 장치 위치 센서 불일치` 장애를 한 번 주입한다. 실제 센서 진단이 아닌 시뮬레이션 원인이라고 표시한다.
- `장애 확인`을 펼치면 원인, 영향받은 차체, 정지 당시 작업 진행량, 필요한 조치, 이력을 보여준다. 평소에는 한 줄로 접혀 있어 3D 화면을 가리지 않는다.
- `현장 점검 시작`은 점검 이력만 남긴다. 설비는 계속 DOWN이며, 시간 경과만으로 복구되지 않는다.
- 사용자가 센서 재정렬·원점 복귀를 마쳤다고 가정하고 `조치 완료 · 재가동`을 눌러야 2초간 동작 확인을 거쳐 복구한다. 별도 실제 하드웨어 점검을 수행했다는 의미는 아니다.
- 기존 모델의 `fail_cell()`과 `recover_cell()`을 통해 실제 생산 상태를 변경한다. 정지 중 차체/작업 ID/남은 작업을 보존하며 복구 후 남은 부분부터 진행한다. 다른 정상 설비와 운송의 시계는 계속 진행한다.
- 사람의 대응을 기다리는 시간은 데모 생산 제한 시간에서 제외한다. 브라우저 새로고침이나 상세 패널 접기는 복구가 아니며, `중단`은 기존과 같이 실행 종료다.

## 제어와 기록

- 브라우저 → 개발 서버의 기존 동일 출처 JSON 제어 경로 → 현재 실행 자식 프로세스의 stdin → 시뮬레이션 단일 쓰기 스레드 순으로 처리한다.
- 현재 run/장애 ID/단계를 확인하며, 점검 전 재가동, 오래된 run, 중복 조작과 동시 요청은 거부한다. Python의 실제 처리 응답을 받은 후 UI가 갱신된다. 제어 연결 단절 시 조작을 비활성화한다.
- 원인·발생/점검/조치/복구 시각·조작 주체는 실행 증거 폴더의 `maintenance.json`에 원자적으로 저장한다. 실제 DOWN/복구와 생산 기록은 기존 `originals.ndjson`·수집/운영 경로로 전달된다.
- 상세 조치 이력은 현재 개발 실행기가 보유한 현재/직전 실행을 UI에 표시한다. 개발 서버 재시작 후 과거 상세 이력 조회 API와 DB 저장 확장은 아직 없다. 파일 증거는 남는다. 정적 배포 서버에는 기존과 같이 프로세스 실행·복구 제어기가 없다.
- 이번 작업은 수동 장애 대응 범위다. 앞서 검토한 후면 AMR 배치와 2키트 선보급/소비/재고 연동은 아직 시안·설계 상태다.

## 검증

- Python 전체 53개 테스트 통과. 장애 유지, 점검만 한 상태의 정지 유지, 정상 다른 셀의 진행, 2초 확인, 남은 작업 보존, 중복/오래된 조작 거부, 정책 4 실제 경로로 3대 생산·최종 복귀까지 검증했다.
- 콘솔 전체 18개 테스트 통과. 수동 시나리오 실행, 출처 검증, 단계·run 검증, 명령 전달과 처리 응답, 완료 후 상태 보존을 포함한다.
- 콘솔 빌드 성공. 기존 대형 청크 경고만 존재.
- Chrome에서 직접 새 실행 `run-20261010-2a510b2987194646995dc7490dea3fc6`을 시작하고 두 버튼을 눌렀다. 시뮬레이션 시각 22.7초 장애 발생 → 34.4초 점검 시작 → 54.7초 조치 완료 → 56.7초 복구. 총 정지 34초 동안 1/4초 진행량과 남은 작업 3초가 보존됐다.
- 브라우저 콘솔 오류·경고 없음. 캡처: `manual-recovery-detected.png`, `manual-recovery-inspecting.png`, `manual-recovery-resolved.png`.
- 실제 실행 완료: 원본 이벤트 870개, 장애 중 DOWN 스냅샷 69개 모두 남은 작업 3초를 보존했다. 복구 시점에도 3초에서 이어가며 해당 작업 완료 이벤트는 정확히 1개다. 차체 3대 모두 PASS/GOOD, 모든 차량 IDLE 및 AGV 초기 위치 복귀를 확인했다.
- `verify-3d-motion.mjs --require-forward --require-final-home`으로 실제 관측과 렌더링 보간의 위치 일치, 설비·차량 충돌 여유, 적재 전진, 모든 생산 종료 후 외곽 복귀를 통과했다.
- 최종 Chrome 화면에서도 실행 완료, 검사 통과 3대, 두 AGV 대기, 수동 조치 이력을 확인했다. 최종 캡처는 `manual-recovery-finished.png`다.
- 결과 파일: `docs/development/3d-review/manual-recovery-verification.json`, `manual-recovery-motion-verification.json`. 원본 증거: `.build-cache/connected-demo/run-20261010-2a510b2987194646995dc7490dea3fc6/`.

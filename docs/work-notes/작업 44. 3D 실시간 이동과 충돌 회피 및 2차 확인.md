# 작업 44. 3D 실시간 이동과 충돌 회피 및 2차 확인

작성일: 2026-10-10 · 상태: 구현·검증 완료, 사용자 2차 확인 대기

사용자가 1차 시안의 색감을 승인하고 실제 연결을 요청했다. 추가로 설비 관통·차량 중첩 금지와 회피 주행을 요구했다. 기존 계획에서 후속으로 분류했던 주행 충돌 회피를 이번 범위로 옮겼다. AGV별 1인칭 시점은 요청대로 후속으로 남긴다.

## 구현

- Python `traffic.py`: 설비·Bay·보관 구역의 고체 영역, 공장 경계, 적재물을 포함하는 차량 반경 24와 여유 거리 3을 적용한다. 좌표는 기존 모델 단위이며 실측 미터가 아니다.
- 원래 위치는 접안 좌표로 유지하고 고체 설비를 통로 옆에 배치한다. 서로 다른 3개 주차 위치로 출발·복귀한다. 취소된 운송도 접안 위치를 비우고 주차 위치로 복귀한다.
- 확장된 장애물 모서리를 이용한 경로 탐색, 전체 경로 통행 예약, 우회·양보 대기, 서로 목적지를 막는 차량의 빈 공간 양보를 구현한다. 진행 중인 경로는 같은 tick 전체에서 보호하여 차량 갱신 순서에 따른 관통도 막는다. 우회 거리가 늘면 이동 시간도 늘고 설정 속도를 초과하지 않는다.
- 새 웹 실행은 `--traffic`을 자동 적용한다. 기존 CLI·기록은 하위 호환을 유지하며 새 CLI 실행에는 이 옵션을 지정한다. 기존 기록의 좌표를 사후 수정하지 않는다.
- 수신/운영 v1 validator에 선택적 `config.traffic`, `vehicles[].traffic`을 함께 추가했다. 서버는 원본 경로·진행량을 그대로 저장·전달한다. 상세 계약은 `contracts/v1/events.md`에 기록했다.
- Three.js 객체는 SSE마다 재생성하지 않고 갱신한다. 같은 실행·epoch·차량 단계·적재·경로인 연속 관측에서만 경로 진행량을 함께 보간한다. 다른 경우 전체 차량을 한 시점의 확정 위치로 맞춘다. 외삽하지 않고 일시정지·오래된 보고·숨김에서는 마지막 확인 위치를 표시한다.
- 실제 적재만 차량 위에 표시한다. 예약 슬롯에는 차체를 미리 만들지 않는다. Bay 색상, 설비 상태등, 차량 양보 텍스트, 기존 차량/차체/셀/Bay 상세창을 연결했다. 입고·출고 보관은 대표 차체와 수량으로 집계하며 개별 차체는 검색/상세에서 모두 조회한다.
- 승인된 흰색·남색·파란색 스타일을 유지한다. 2D/3D 전환, 카메라 조작, 이름/경로 표시, WebGL 오류 복구 및 2D 복귀를 유지한다.

## 검증

- Python 29개 통과: 기존 생산·예약·소유권 회귀, P0 전체 완료, 장애물 우회·경로 없음, 매 tick의 차체 외곽과 이동 선분, 차량 상대 이동 거리, 일시정지, 목적지 교환 양보, 취소 후 접안 해제, Bay 용량 2/3/4와 100/500ms tick.
- Node 9개 통과: 기존 feed/조회 범위, 보간 경로 모서리·외삽 방지·실행/epoch/적재 경계, 실제 슬롯과 적재 소유권, 웹 실행기의 교통 옵션.
- Java 수신 6개·운영 5개 통과 및 패키징 성공. 환경 전용 DB 통합 테스트 7개/6개는 해당 환경변수가 없어 건너뛰었다. 대신 아래 실제 개발 스택의 TCP→DB→REST/SSE 전체 실행을 확인했다.
- Vite 프로덕션 빌드 성공. 3D는 별도 lazy chunk이며 약 150KB gzip. 기존 품질 차트와 함께 500KB chunk 경고는 남아 있다. 새 GPU 성능 수치나 FPS 보장은 측정하지 않았다.
- 실제 실행 `run-20261010-00661b6a1e9a44329886f8c68195791d`: 5대, 만석/예약/이동/설비 DOWN/복구/부품 운송 포함. 736개 원본 이벤트, 541개 snapshot, GOOD/PASS 4대와 HOLD/FAIL 1대, 모든 차량 별도 주차 위치에서 IDLE. 운영 API `dataStatus=FINISHED`, 최종 snapshot 순번 735 (그 다음 736은 RUN_FINISHED).
- 실제 기록에서 433개 보간 가능 구간과 총 3,787개 차량군 표시 표본을 검사했다. 장애물·공장 경계 침범 및 차량 중첩 없음. 최소 차량 중심 거리 55.306, 정책 최소 거리 51. 최대 이벤트 6,752 bytes. [검증 수치](../development/3d-review/traffic-verification.json).
- 동일 tick 통행 보호와 취소 복귀까지 반영한 최종 코드로 정상 생산도 재실행했다. `run-20261010-613eed3af80f466fb4417bb9c8264b2b`: 185개 이벤트, 147개 snapshot, 운영 API FINISHED·GOOD/PASS 1대·전 차량 IDLE. [최종 정상 실행 검증](../development/3d-review/normal-verification.json).
- Chrome: 실제 실시간 차량 위치·적재와 상세창, 양보 대기, 사선/평면/확대, 2D↔3D 재진입 확인. 390px 화면에서 문서 폭 381px로 수평 넘침 없음; HOLD/FAIL 차체 상세 조회 확인. 개발 console 오류/경고 없음.
- 해당 검증 소스만 15초 중단했다가 자동 복귀시켜 ‘보고 지연 · 마지막 확인값’과 이후 ‘실시간 관측’을 확인했다. 기존 DB/실행 기록과 볼륨은 보존했다.

## 확인 화면과 경계

`http://127.0.0.1:5174/?view=3d`에서 새 시뮬레이션 시작을 누르면 된다. 5대 시나리오는 만석·장애·복구와 AMR까지 포함하고, 1대/3대는 정상 생산 흐름이다. 개발 서버의 실행 버튼은 로컬 Python 환경과 수신 9090·운영 8082 연결이 필요하다.

2차 확인 대상은 차량 이동·우회/대기 방식, 정보 가독성, 카메라·선택 조작이다. 사용자 확인 뒤 마무리 조정을 진행한다. 5174 개발 화면을 제공했으며 5173 기존 콘솔 이미지는 이번 단계에서 교체하지 않았다.

현재 범위는 충돌을 예방하는 운동학적 물류 시뮬레이션이다. 충격·마찰·가감속·조향 한계와 실제 로봇팔 인계의 강체 동역학까지 구현한 것은 아니다. 접안 후 설비 내부로의 인계는 확정 상태 전환으로 표시한다. 실물 공장과 동기화한 운영 디지털 트윈이라고 주장하지 않는다.

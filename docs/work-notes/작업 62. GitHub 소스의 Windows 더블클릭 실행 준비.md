# 작업 62. GitHub 소스의 Windows 더블클릭 실행 준비

2026-10-11

사용자는 Windows 64비트에서 GitHub 소스를 내려받아 실행할 수 있게 준비하되 ZIP은 만들지 말라고 요청했다. 기존 `windows-dev.ps1`은 도구 자동 준비·빌드·기동·종료를 지원했다. 이를 명령어를 입력하지 않고 사용할 수 있도록 루트 진입점과 안내를 보완했다.

## 변경

- `01-prepare-windows.cmd`: 기존 `setup` 성공 후 `build` 실행. 오류가 나면 다음 단계를 실행하지 않고 창에 내용을 남긴다.
- `02-start-windows.cmd`: `up`의 준비 상태 확인이 성공한 뒤 브라우저를 연다. 기존 실행 중인 서버는 기존 스크립트의 프로세스 확인을 사용한다.
- `03-stop-windows.cmd`: 기존 `down`으로 관리 중인 시뮬레이션·서버를 종료하고 DB를 보존한다.
- `04-status-windows.cmd`: 서버·DB 상태를 보여준다.
- CMD는 ASCII/CRLF이며 `%~dp0`를 인용해 현재 터미널 위치와 무관하게 자신의 프로젝트 스크립트를 찾는다. PowerShell 실행 정책은 해당 프로세스에만 적용한다.
- `windows-dev.ps1`은 Windows x64 대상 여부를 확인하고, 실행 시 embeddable Python 경로를 현재 폴더에 다시 맞춘다. 환경 파일 누락 안내, 실행 중 서버 재빌드 방지와 최신 웹 시나리오 안내도 보완했다.
- [처음 실행 안내](../../WINDOWS-START.md), 루트 README와 기존 Windows/다른 컴퓨터 안내를 연결했다.

## 사용 순서

최초 인터넷 연결 상태에서 전체 소스를 내려받아 압축 해제하고 **01 준비 → 02 실행**. 다음부터 **02 실행**, 종료는 **03 종료**다. 웹에서 1대/3대 정상 또는 5대 수동 장애 복구를 시작한다. Git·Docker 사전 설치는 필요하지 않으며 도구와 의존성은 준비 단계에서 내려받는다. 오프라인 설치 패키지가 아니다.

기존 `.env`와 `.build-cache`는 Git 제외 대상이다. 새 컴퓨터의 설정과 DB는 새로 만든다. 소스 갱신 시 종료 후 준비·빌드를 다시 수행한다. 최신 소스와 새 실행 파일을 GitHub에 반영해야 원격에서 내려받을 수 있다.

## 검증

현재 macOS에서 Git 추적 대상 및 미추적 최신 소스를 별도 폴더로 복사해 Git 없는 전달 폴더를 구성했다. 최초 상태에는 `.git`, `.env`, `.build-cache`, node_modules와 JAR이 없다. 압축 파일은 만들지 않았다.

- 별도 폴더에서 기존 실행기와 같은 TCP 환경 변수를 지정한 Python `--check-config` 성공.
- 잠금 파일의 npm 의존성을 기존 다운로드 캐시로 오프라인 설치한 뒤 Vue 프로덕션 빌드 성공.
- 별도 폴더에서 기존 Maven 다운로드 캐시를 사용해 Java 서버 2개를 각각 오프라인 package 빌드 성공. 테스트 실행은 `-DskipTests`로 생략했다.
- 실행 파일의 CRLF/ASCII, 인용된 프로젝트 상대 경로, 의존 파일 포함, `.env`/`.build-cache` Git 제외, 문서 링크 및 `git diff --check` 확인.

이 결과는 Git 메타데이터나 기존 빌드 산출물이 없어도 소스를 구성·빌드할 수 있는지 확인한 것이다. **현재 환경에서 Windows CMD/PowerShell 자체 실행과 새 Windows의 최초 다운로드·DB 기동·전체 시연은 검증하지 못했다.** 기존 Windows x64 기반의 과거 검증과 이번 최신 버전 검증 범위를 구분한다.

ZIP 생성, Git commit/push, 실행 중인 공장·DB의 재시작 또는 삭제는 수행하지 않았다.

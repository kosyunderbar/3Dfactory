# 작업 60. 현재 3D·AMR·수동 복구 기준 문서 갱신

2026-10-11

사용자 요청에 따라 기획·해설·실행 안내·기능과 시연·포트폴리오 문서를 작업 59까지의 현재 소스와 검증 기록에 맞췄다. 애플리케이션 코드와 실행 중인 시뮬레이션은 변경하지 않았다.

## 반영한 기준

- 일반 시나리오를 **1대 정상 / 3대 정상 / 5대 장애·수동 복구**로 통일했다. 차체 대수와 차량 수(AGV 2·AMR 1)를 구분했다.
- 상세 Three.js 코드 모델, 2D 대체 보기, AGV·AMR 3인칭 추적 및 AGV 전면 시점을 설명했다. Blender/GLB와 실센서 연동은 완료 기능으로 쓰지 않았다.
- 통로 A*·구간 예약과 양보·적재 전진·최종 외곽 복귀를 반영했다. 빈 셀 직접 인계, 대기 시 Bay 사용, AGV의 Bay 픽업 완료 때 슬롯 반환과 이후 셀 인계를 구분했다.
- 후면 AMR 실제 보급, ASM 작업 시작 시 키트 소비, 운송 중 재고와 남은 수요를 고려한 선보급을 설명했다. 기본 초기 재고는 공정별 2키트이며 일반 1대 실행에도 적용된다.
- 수동 장애의 원인·현장 점검·조치 완료·2초 동작 확인·작업 재개와 알람 확인의 차이를 설명했다.
- Docker 정적 화면과 로컬 Vite 실행기의 제어 범위를 구분했다. Python 경로, 기본 TCP 9090, Vite 종료 시 관리 프로세스 중단, Windows 네이티브 실행 절차를 실제 스크립트와 대조했다.
- 이력서 문구·면접 설명·시연 순서를 현재 기능에 맞추고, 사용자 기획·검토와 AI 구현 기여를 구분하는 기존 원칙을 유지했다.

## 검증과 범위

현재 소스의 시나리오 매핑·화면 버튼·실행기·부품 및 운송 규칙을 대조하고, 문서의 상대 경로와 코드 블록, `git diff --check`를 확인했다. 문서만 변경했으므로 앱 테스트·부하 실험·시뮬레이션은 다시 실행하지 않았다.

Python 58개·콘솔 19개 및 빌드 성공은 작업 58·59의 기존 검증 결과다. 현재 5대 시나리오는 오프라인 전체 완료와 실제 웹의 투입·수동 점검 대기까지 확인한 기록이며, 실제 연결 전체 완료 기록은 당시 3대 실행임을 구분했다. 과거 S08/S09의 2D 성능 수치를 최신 3D 성능으로 재사용하지 않았다.

과거 작업 노트와 검증 산출물은 당시 이력으로 보존했다. Git commit/push, 새 컴퓨터 최초 실행, 최신 3D GPU 성능 측정은 이번 작업에 포함하지 않았다.
